# Как собрать «Нарезка Shorts.exe» в облаке GitHub

Сборка идёт на чужом компьютере (виртуальная машина GitHub) — на вашем ничего
устанавливать, компилировать и «разрешать» не нужно. Готовый `.exe` скачивается
обычной ссылкой.

**Что уже готово в проекте** (менять ничего не надо):

| Файл | Зачем |
| --- | --- |
| `.github/workflows/build-exe.yml` | Собирает `.exe`, проверяет, что он запускается, и выкладывает в артефакты; по тегу — в Releases |
| `.github/workflows/build-msix.yml` | Пакет для Microsoft Store (запускается только вручную) |
| `.gitignore` | Чтобы на GitHub не уехали 1,5 ГБ окружения, кэша модели и сборок |
| `.gitattributes` | Чтобы git не испортил `ЗАПУСК.bat` и `Нарезка Shorts.cmd` (они в cp866) |
| `загрузить_на_github.py` | Загрузка проекта на GitHub **без установленного git** |

> **Честно о главном.** Сборка в облаке снимает проблему «на этом компьютере
> собрать нельзя». Но запуск **неподписанного** `.exe` на этом компьютере
> по-прежнему блокирует Smart App Control — блокировка не зависит от того, где
> файл собран. То есть:
>
> * **раздать другим людям** — да, скачанный `.exe` работает у них (у кого нет
>   такой политики);
> * **запустить у себя** — только если выключить Smart App Control (Windows
>   Security → App & browser control → Smart App Control → Off; обратно
>   включается лишь переустановкой Windows), либо подписать `.exe` настоящим
>   сертификатом подписи кода, либо взять пакет из Microsoft Store (его подписывает
>   Microsoft);
> * **прямо сейчас на этом ПК** работает `Нарезка Shorts.cmd`.

## Путь A. Без установки git (рекомендую)

Обычный git на компьютере не установлен, а установщики Windows может блокировать
той же политикой, что и установщик python.org. Поэтому проект уезжает на GitHub
скриптом на уже имеющемся Python — через API GitHub.

### Шаг 1. Создайте пустой репозиторий (1 минута)

1. Откройте <https://github.com/new>.
2. **Repository name**: например `shorts-cutter`.
3. **Public** или **Private** — см. врезку про лимиты ниже.
4. **Ничего не отмечайте**: ни README, ни .gitignore, ни лицензию. С ними тоже
   сработает, но в истории появится лишний первый коммит от GitHub, а наш
   `.gitignore` уже готов в проекте.
5. **Create repository**.

### Шаг 2. Создайте токен доступа (1 минута)

1. <https://github.com/settings/tokens?type=beta> → **Generate new token**.
2. **Token name**: `shorts-cutter-upload`.
3. **Expiration**: 90 дней (потом можно выпустить новый).
4. **Repository access** → *Only select repositories* → выберите `shorts-cutter`.
5. **Permissions** → *Repository permissions*:
   - **Contents** → *Read and write*
   - **Workflows** → *Read and write* — обязательно: в проекте есть файлы
     `.github/workflows/`, а без этого права GitHub не даст их записать (проверено
     на практике: с одним лишь Contents запись отклоняется).
6. **Generate token** и скопируйте значение вида `github_pat_…` (показывается один раз).

### Шаг 3. Загрузите проект

Откройте PowerShell и выполните (замените логин и имя репозитория):

```powershell
cd "C:\Users\nadop\OneDrive\Desktop\кит\shorts-cutter"

# сначала примерка: что именно уедет на GitHub (ничего не отправляется)
py -3 загрузить_на_github.py --repo ВАШ_ЛОГИН/shorts-cutter --dry-run

# теперь сама загрузка
$env:GITHUB_TOKEN = "вставьте_сюда_токен"
py -3 загрузить_на_github.py --repo ВАШ_ЛОГИН/shorts-cutter
```

Ожидаемый итог: строка вида «Файлов к загрузке: 58 (2.4 МБ)», затем список
файлов, затем «Готово. Коммит …». Проверить, что ничего лишнего не уехало,
можно на странице репозитория — там должно быть около 60 файлов и ни одной
папки `.venv`.

Токен из истории команд можно убрать: `Remove-Item Env:\GITHUB_TOKEN`.

### Шаг 4. Сборка запускается сама

Первый коммит в ветку `main` уже запускает сборку (так настроен workflow).
Смотрите: <https://github.com/ВАШ_ЛОГИН/shorts-cutter/actions> → запуск
«Сборка .exe для Windows».

Запустить вручную (например, повторно): **Actions** → слева «Сборка .exe для
Windows» → **Run workflow** → ветка `main` → **Run workflow**.

Сборка идёт 5–10 минут: сначала юнит-тесты (`python main.py --selftest`), потом
PyInstaller, потом проверка «.exe действительно запускается» (`--check`).

### Шаг 5. Скачайте .exe

На странице запуска внизу — раздел **Artifacts** → `narezka-shorts-exe-no-subtitles.zip`
→ распаковать → внутри `Нарезка Shorts.exe` (~49 МБ, внутри tkinter, Tcl/Tk и ffmpeg,
Python у пользователя не нужен).

Проверка на своей машине (запустится не везде — см. врезку выше):

```powershell
& ".\Нарезка Shorts.exe" --check
```

Отчёт печатается и дублируется в `shorts_cutter.log` рядом с файлом.

### Шаг 6. Нужна ссылка для раздачи — сделайте релиз

1. На GitHub: **Releases** → **Draft a new release**.
2. **Choose a tag** → впишите `v1.0.0` → **Create new tag on publish**.
3. **Publish release**.
4. Тег запускает сборку **обоих** вариантов, и workflow сам приложит их к этому
   релизу: портативный `Нарезка Shorts.exe` и
   `Нарезка-Shorts-с-субтитрами.zip` (через 15–25 минут на странице релиза
   появятся оба файла).

Если автоматический запуск по тегу не сработал: запустите workflow вручную
(**Run workflow**), скачайте артефакт и перетащите файл в окно редактирования
релиза — результат тот же, только руками.

## Вариант «с субтитрами» (~370 МБ в папке, ~180 МБ архив)

Приложение умеет распознавать речь (`faster-whisper`), но в базовую сборку этот
модуль не входит, чтобы файл был 50 МБ, а не 600. Второй вариант собирается:

* **автоматически при создании тега** версии (`v1.0.0`) — вместе с портативным,
  оба файла попадают в релиз: это самый простой путь, дополнительных прав токену
  не нужно;
* **вручную**: **Actions** → «Сборка .exe для Windows» → **Run workflow** →
  галочка **«Собрать с распознаванием речи»** → **Run workflow**. Для ручного
  запуска у токена дополнительно нужно право **Actions: Read and write**.

Что важно знать:

* В субтитрах получается **папка** (а не один файл), упакованная в
  `Нарезка-Shorts-с-субтитрами.zip`: под 370 МБ распаковка во временную папку
  при каждом запуске была бы слишком долгой. Распаковать и запускать `.exe`
  внутри папки.
* Перед выкладкой сборка сама проверяет распознавание **внутри** собранной
  программы (`--check-subtitles`): импортируются ctranslate2, onnxruntime и av,
  загружается модель и распознаётся короткий звук. Если это падает, файлы в
  релиз не попадут.
* Сама модель распознавания (`small`, 464 МБ) в сборку **не** входит: она
  скачается при первом включении субтитров — то есть на машине пользователя
  нужен интернет один раз, дальше всё офлайн. Ускорить можно, положив папку
  `faster-whisper-small` рядом с `.exe` в `models\` (приложение само её найдёт).
* На бесплатном тарифе включено 500 МБ хранилища артефактов (общее с GitHub
  Packages), поэтому такую сборку лучше скачать и сразу удалить артефакт
  (в workflow срок хранения и так 30 дней). Обычная сборка на 49 МБ в лимит
  влезает свободно.

## Про лимиты GitHub Actions

* Публичный репозиторий: стандартные раннеры бесплатны, ограничений по минутам нет.
* Приватный: бесплатный тариф даёт $12 расчётного лимита в месяц; минута
  Windows-раннера стоит $0.010, то есть примерно 1200 минут — это ~150 сборок
  по 8 минут. Когда лимит исчерпан и способ оплаты не привязан, запуски
  блокируются до следующего месяца.
* Наш `.gitignore` хранит в репозитории только исходники (2,4 МБ), поэтому
  клонирование и сборка быстрые.

## Путь B. Если решите поставить обычный git

```powershell
winget install --id Git.Git -e --source winget
```

Если установщик заблокирован политикой — остаётся путь A. Дальше:

```powershell
cd "C:\Users\nadop\OneDrive\Desktop\кит\shorts-cutter"

git init -b main
git config user.name "Ваше Имя"
git config user.email "почта@example.com"

git add -A
git status --short          # должно быть ~60 файлов и НИ ОДНОГО из .venv, dist, _install_test
git commit -m "Нарезка Shorts: исходники и сборка .exe в облаке"

git remote add origin https://github.com/ВАШ_ЛОГИН/shorts-cutter.git
git push -u origin main
```

При первом `push` откроется окно входа в GitHub (Git Credential Manager) — это
нормально, токен вручную вводить не нужно.

Дальше так же: Actions → сборка → Artifacts. Обновление после правок —
`git add -A; git commit -m "правки"; git push`.

Тег для релиза:

```powershell
git tag v1.0.1
git push origin v1.0.1
```

## Если токен отказывает в записи (403)

Скрипт проверяет это до загрузки и сам печатает, какого права не хватает: GitHub
сообщает его в заголовке ответа. Нужны **все три** вещи:

| Что | Где в настройках токена | Признак, что забыли |
| --- | --- | --- |
| Репозиторий добавлен в доступ | **Repository access** → *Only select repositories* → сам репозиторий | `403`, хотя репозиторий «открывается»: публичный репозиторий читается кем угодно и без прав, это сбивает с толку |
| **Contents: Read and write** | Repository permissions → Contents | `403`, в ответе `contents=write` |
| **Workflows: Read and write** | Repository permissions → Workflows | `403` при записи `.github/workflows/*.yml` |

Меняйте права в том же токене (Edit → Save changes) — значение остаётся прежним,
выпускать новый не нужно.

**Пустой репозиторий — это нормально.** Пока в репозитории нет ни одного коммита,
GitHub отказывает всему Git Data API: даже создание файла отвечает
`409 Git Repository is empty`. Скрипт обходит это сам — делает служебный первый
коммит через Contents API, после чего заливает проект обычным путём. Служебный
файл `.gitkeep` в итоговом состоянии репозитория не остаётся.

## Что делать, если что-то не так

| Сообщение / ситуация | Что это значит и что делать |
| --- | --- |
| `GitHub ответил 401: Bad credentials` | Токен неверный или истёк. Выпустите новый (шаг 2) |
| `GitHub ответил 404` | Опечатка в `логин/репозиторий` либо у токена нет доступа к этому репозиторию |
| `Репозитория нет или у токена нет к нему доступа` | Проверьте право **Contents: Read and write** |
| `В токене есть символы не из латиницы` | Скопировался лишний текст или кавычки — скопируйте токен заново |
| Во вкладке Actions нет workflow | Не уехала папка `.github/workflows`. Проверьте её в репозитории; если её нет — загрузка шла не из папки проекта |
| `Actions` пишет, что workflows отключены | Settings → Actions → General → **Allow all actions and reusable workflows** |
| Шаг «Собрать .exe» упал | Откройте лог шага: там вывод PyInstaller с настоящей причиной |
| Шаг «Проверить, что .exe запускается» упал | Сборка собралась, но не стартует — смотрите `shorts_cutter.log` в логе шага |
| Нет кнопки Download у артефакта | Запуск ещё идёт либо истёк срок хранения (30 дней) |
| `.exe` скачался, но Windows не пускает | Smart App Control (см. врезку в начале). Плюс снимите метку «из интернета»: правый клик по файлу → Свойства → **Разблокировать** |
| Хочу, чтобы `.exe` работал у меня без выключения SAC | Нужен сертификат подписи кода или пакет Microsoft Store (`build-msix.yml` + `store/ИНСТРУКЦИЯ-ПУБЛИКАЦИИ.md`) |
