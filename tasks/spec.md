# Техническое задание: приложение «Нарезка Shorts» для Windows

> Вставь этот документ целиком в DeepSeek (или скорми агенту Cline в VS Code — см. раздел 10).

## 1. Общая цель

Написать десктопное приложение для Windows 10/11, которое берёт длинное видео (подкаст, интервью, влог, длительность от 5 минут до 4 часов) и режет его на готовые вертикальные клипы для публикации в YouTube Shorts и TikTok: обрезает фрагменты по отметкам пользователя, кадрирует в вертикальный формат 9:16 и вшивает субтитры.

Пользователь приложения — человек без опыта программирования. Программа должна работать после простого запуска и не требовать ручной установки ffmpeg, кодеков и прочего.

## 2. Технологический стек (обязательный)

- Python 3.11 или новее, только стандартная библиотека + указанные ниже пакеты.
- Графический интерфейс: Tkinter (входит в стандартную поставку Python). Не использовать PyQt/PySide в первой версии.
- Работа с видео: ffmpeg, бинарник которого подгружается из пакета `imageio-ffmpeg` (устанавливается через `pip install imageio-ffmpeg`; путь к бинарнику — `imageio_ffmpeg.get_ffmpeg_exe()`). Не требовать установки ffmpeg в систему.
- Субтитры (опциональный модуль): `faster-whisper`, модель `small` (при первом запуске скачивается пользователем, далее работает офлайн). Если пакет не установлен, функции субтитров отключаются с понятным сообщением, а нарезка продолжает работать.
- Кодировка субтитров поверх видео: фильтр ffmpeg `subtitles` (burn-in). Для этого нужен временный файл .srt или фильтр `drawtext`/`subtitles` с экранированием путей (пути с кириллицей и пробелами обязательно тестировать).
- Оформление кода: один файл `main.py` не более ~1200 строк либо разбивка на модули `ui.py`, `cutting.py`, `subtitles.py`. Комментарии на русском.

## 3. Функциональные требования

### 3.1. Выбор видео
- Кнопка «Выбрать видео» открывает диалог выбора файла .mp4/.mov/.mkv/.avi/.webm.
- После выбора показывать: имя файла, длительность в формате ЧЧ:ММ:СС, разрешение и fps (получать через `ffprobe` из imageio-ffmpeg — есть `imageio_ffmpeg.get_ffmpeg_exe()` рядом с bin; ffprobe можно заменить разбором вывода `ffmpeg -i file`, допустимо).

### 3.2. Список клипов (интервалов)
- Пользователь добавляет интервалы строкой в поле формата `ММ:СС-ММ:СС` или `ЧЧ:ММ:СС-ЧЧ:ММ:СС` (можно смешивать форматы, допустимы пробелы). Также кнопка «Добавить текущий интервал» — интервал берётся из двух полей «Начало» и «Конец» с таймкодами.
- Каждая строка списка показывает: номер клипа, интервал, длительность в секундах.
- Кнопка «Проверить интервалы»: подсветить ошибки (конец раньше начала, конец за пределами видео, пересечение интервалов между собой).
- Кнопки: удалить выбранный клип, очистить список.
- Кнопка «Нарезать подряд»: сгенерировать N равных клипов заданной длительности (поле «длина клипа, сек») по всему видео — для случая, когда пользователь не хочет размечать вручную.

### 3.3. Настройки экспорта
- Формат вывода: «Вертикаль 9:16 (1080×1920)» (по умолчанию) или «Оставить как есть». При вертикальном формате: центральный кроп исходного кадра до 9:16, затем масштаб до 1080×1920. Опция-переключатель «Автодетект лица» — в первой версии НЕ реализовывать, оставить место в настройках (серым, с подписью «позже»).
- Субтитры: выключено (по умолчанию) / включено. При включении: распознать речь выбранного интервала через faster-whisper, сгенерировать .srt, вшить поверх клипа. Настройки: размер шрифта (по умолчанию 48), положение (низ/центр), цвет (белый/жёлтый), обводка чёрная всегда.
- Качество экспорта: поле CRF (по умолчанию 20, диапазон 16–28, подпись «меньше — лучше качество и больше файл»).
- Папка вывода: по умолчанию — подпапка «Shorts» рядом с исходным видео; можно задать свою через диалог.

### 3.4. Нарезка
- Команда «Нарезать» обрабатывает клипы последовательно. Для каждого клипа:
  1. ffmpeg: декодировать исходник с точными границами (`-ss <start> -t <dur>` перед `-i`), фильтр-цепочка кропа/масштаба, вшивание субтитров (если включены), кодирование H.264 (`libx264`, CRF из настроек, preset `veryfast`, `pix_fmt yuv420p`) + AAC 128k.
  2. Точное обрезание границ важнее скорости: копирование потока (`-c copy`) НЕ использовать — границы сдвинутся по ключевым кадрам.
- Прогресс-бар с процентами по каждому клипу (парсить вывод ffmpeg по строке `time=`), кнопка «Отмена» (убить текущий процесс ffmpeg, корректно закрыть частичный файл).
- Имена файлов: `<имя исходника>_клип01.mp4`, `_клип02` и т.д. Если файл существует — не перезаписывать, добавить суффикс `_2`.
- По завершении: окно со списком готовых файлов и кнопкой «Открыть папку» (`os.startfile`).

### 3.6. Визуальный стиль (обязательный)
- Тёмная тема. Основной фон окна и панелей — тёмно-синий (например, #0D1B2A для фона, #1B263B для панелей и полей ввода).
- Акцентный цвет — тёмно-красный (например, #8B0000 или #A4161A): кнопки «Нарезать» и «Отмена», выделение выбранных строк списка, заголовки секций.
- Обычный текст — светло-серый (#E0E1DD), второстепенный — приглушённый (#A9B4C2). Ошибки в списке интервалов подсвечивать тёмно-красным фоном строки, готовые клипы — приглушённым зелёным (#4A7C59) только для статуса.
- Стиль применять единообразно: настройка виджетов через общий словарь цветов/шрифтов в отдельном модуле `theme.py`. Не оставлять элементы с системной светлой темой.
- Шрифт интерфейса — системный Segoe UI; не использовать экзотические шрифты.

### 3.7. Логи и ошибки
- Все операции писать в файл `shorts_cutter.log` рядом с программой: время, команда ffmpeg (целиком), код возврата.
- Любая ошибка — понятное окно на русском («ffmpeg не смог открыть файл: …»), безtraceback на экран пользователя.

## 4. Нефункциональные требования

- Все тексты интерфейса — на русском.
- Внешний вид — по разделу 3.6: тёмно-синяя тема с тёмно-красными акцентами, никаких светлых элементов по умолчанию.
- Приложение не должно зависать во время нарезки: ffmpeg запускать в отдельном потоке, UI обновлять через `queue`/`after`.
- Работать офлайн; единственное обращение в интернет — первичное скачивание модели faster-whisper, с явным сообщением об этом.
- Не требовать прав администратора.
- Запуск: `python main.py`. Дополнительно приложить файл `ЗАПУСК.bat` с двумя строками: `pip install -r requirements.txt` и `python main.py`.

## 5. Формат данных

- Интервал пользователь вводит строкой; парсер должен выдерживать: `1:23-2:45`, `01:23:45-01:25:00`, `00:10 - 00:30`, лишние пробелы.
- Внутри приложения время — целые секунды или float; в логи и имена файлов не попадает.

## 6. Тесты и критерии приёмки

1. Выбор видео 5+ минут → длительность определена верно.
2. Интервалы `12:30-13:20`, `1:05:00-1:06:00`, `0:30-0:45` парсятся корректно; строка `13:20-12:30` помечается ошибкой.
3. Нарезка трёх клипов без субтитров, вертикаль 9:16: выходные файлы 1080×1920, длительность каждого в пределах ±1 сек от заданной, звук не рассинхронизирован (проверить на глаз/на слух).
4. Нарезка с субтитрами: текст совпадает с речью, читается на вертикальном кадре, не обрезается по краям.
5. Кириллица и пробелы в имени исходного файла и пути вывода не ломают обработку.
6. Отмена посреди обработки: процесс ffmpeg умирает, приложение остаётся рабочим.
7. При отключённом модуле субтитров нарезка работает, кнопки субтитров деактивированы с подсказкой.

## 7. Этапы разработки (реализовывать по порядку, демонстрируя результат после каждого)

1. **Этап 1 — каркас:** окно, выбор файла, показ длительности, парсер интервалов, список клипов, оформление окна по разделу 3.6 (тёмно-синяя тема, тёмно-красные акценты) уже на этом этапе.
2. **Этап 2 — нарезка:** ffmpeg через imageio-ffmpeg, кроп в 9:16, прогресс, отмена, лог.
3. **Этап 3 — субтитры:** интеграция faster-whisper (модуль-обёртка, graceful fallback), генерация .srt, burn-in через ffmpeg.
4. **Этап 4 — удобства:** «Нарезать подряд», открытие папки, суффиксы при конфликтах имён, полировка сообщений об ошибках.
5. **Этап 5 (задел на будущее, не реализовывать):** автодетект лица, автоотбор ярких моментов по паузам/всплескам речи, прямая загрузка в TikTok/YouTube.

## 8. Что явно НЕ входит в первую версию

- Прямая выгрузка в YouTube/TikTok/ВК через API.
- Автоматический выбор «лучших» фрагментов.
- Замена/очистка аудио, фильтры шумов.
- Массовая обработка нескольких файлов за раз.

## 9. Ограничения и риски

- Пути с кириллицей: при передаче пути в ffmpeg-фильтр `subtitles` требуется особое экранирование (двойные слэши, апострофы). Обязательно покрыть тестом.
- faster-whisper тормозит на CPU: для модели `small` норма 1–3× длительности аудио; предупредить пользователя о времени обработки перед стартом.
- Высокие разрешения исходника (4K): кроп должен происходить ДО масштабирования, иначе память и скорость страдают.
- Не использовать функции, отсутствующие в Python 3.11, и пакеты, требующие компиляции на Windows.
